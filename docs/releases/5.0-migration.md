本页记录下一主版本的迁移要求。5.0 尚在准备中；本页不证明包已发布、安装已验收或生产门禁已通过。

## 托管应用必须重新编译

`SonnetDB.IO.SpanReader`、`SpanWriter` 及 Frame 信封、服务/操作码等公共类型从 `SonnetDB.Core` 移到独立的 `SonnetDB.Protocol` 程序集，保留原命名空间。没有旧 Core 的类型转发层，使用旧二进制的应用及第三方 provider 必须更新引用并重新编译。

`SonnetDB.Sql.Ast.PaginationSpec.Offset` 和 `Fetch` 从 `int` / `int?` 改为 `long` / `long?`。直接使用 AST 的调用方应更新变量及接口；需要收窄到 `int` 时显式检查范围，不能静默截断。

统一升级同一进程内的 SonnetDB 包及上层 provider，并验证其实际使用的入口。4.0 编译产物不能直接替换 DLL 后宣称兼容；已有 REST/Frame 功能的兼容证据也不能代替所有新增功能的协议协商验收。

## 选择接入包

| 需求 | 包与依赖 |
| --- | --- |
| 只使用共享 Frame 信封及二进制基础类型 | `SonnetDB.Protocol`，不加载引擎 |
| 原生 HTTP/2 Frame 远程传输 | `SonnetDB.Client` → `SonnetDB.Protocol`；当前是有界传输基础层，不等于全部模型的 typed SDK |
| 嵌入式引擎 | `SonnetDB.Core` → `SonnetDB.Protocol` |
| ADO.NET / ORM | `SonnetDB` 及对应 provider，按实际 embedded、REST、Frame 入口验收 |

十个 NuGet 包必须作为同一候选构建、校验并分发。SDK 和完整 Server bundle 必须携带 Protocol/Client 包，使用本地 feed 的消费者也必须能解析到候选 Protocol。包库存合成测试只证明验证器能拒绝缺包；实际包消费另行运行。

`EnablePackageValidation` 继续启用。4.x Core 继续以 4.0.0 为基线；首个 5.0 建立新的主版本 API 边界，后续 5.0 补丁及 5.x 自动以正式 5.0.0 为基线。

## 数据升级与回退

停写并关闭旧进程后，保存可验证的升级前备份，在独立目录验证恢复及 4.0 重开，再用候选在工作副本上验证真实业务数据、索引、事务和重复重开。保留原备份及旧版程序，直到验收完成。

已有新功能包含永久 catalog floor 升级，事务 DDL 可把目录推进到 v19。旧引擎不支持这些目录时，降级必须恢复升级前备份到独立目录，再使用旧版程序；不能承诺只换回旧二进制。若 5.0 上线后已有新写入，恢复旧备份会丢失这些写入，需要独立的数据回补方案。

Frame header 仍为 version 1，不代表数据库目录格式没有升级。单数据库备份也不代表 Server 实例级 MQ、身份配置和全部外部文件均被覆盖。

正式放行仍需最终提交的完整 CI、真实包消费者、升级/恢复证据及发布策略要求的同提交工作流。固定硬件规模、长期运行和干净机器安装按发行声明与渠道分别验收。
