# SonnetDB 5.1.0：可靠恢复与受限远程终态

5.1.0 在 5.0.0 的 API、wire 和数据库迁移边界上继续收口可靠性。当前版本把已验证的 WAL 恢复边界、Frame 终态分类和发行恢复 admission 接入同一份候选证据；它不把尚未完成的环境、真实消费者或完整 typed SDK 路线写成已交付能力。

## 本版本包含

- WAL checkpoint LSN 在写入和回放时拒绝负值。畸形 checkpoint 载荷会以 `InvalidDataException` 失败，避免静默改变恢复起点。
- .NET Frame Client 对封套和响应身份有效但错误载荷畸形的单响应，返回 `frame_terminal` 且保留未知结果；调用方不会把它当作可重试的传输失败。
- tag 恢复脚本的 workflow 等待改为受 `DiscoveryTimeoutMinutes` 和最大轮询次数双重限制的状态查询；失败和超时均明确终止。恢复仍要求批准的 evidence/manifest，未知写入保持 fail-closed。
- .NET 10.0.15、SkiaSharp 4.156.0、CoAP 与 MQTT routing 子模块指针更新，以及既有 atomic WAL v2、KV-LSM、全文预算、Frame TTL opcode 10 和 AOT 边界探针。

## 验证边界

本版本候选必须绑定 tag 指向的完整 commit SHA。源码回归、完整 solution 构建/格式、适用 NativeAOT、包/安装、固定硬件、长稳和公开读回分别记录；其中环境和真实公开发布门禁没有被本地测试替代。当前开放项与逐层状态见 [5.1.0 发布审计](../audits/release-5.1.0-20261115.md)。

5.1.0 沿用 5.0 的主版本迁移合同：Protocol 程序集拆分、分页 `long` API、目录升级和旧引擎拒绝规则不变。升级前停写并保留可验证备份；带有新目录或新段的数据库不能直接换回旧 reader。

## 已知未完成项

EF Provider NativeAOT（#396）仍为 `NOT_SUPPORTED`；九模型 typed Client 与真实 HTTP/2 语言消费者（#397）仍是局部切片；干净系统安装/升级/卸载（#398）、固定硬件容量与恢复（#399）、时序 ms/us/ns（#401）、真实发行恢复和公开读回（#402）、IoTSharp 真实租约消费者（#425）保持 `OPEN` 或 `NOT_RUN`。CoAP C12 与 MQTT R6 的性能、trim/AOT、互操作和现场门禁也独立保留。
