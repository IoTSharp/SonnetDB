# M47 外轮廓与视觉规范

状态：`REVIEW_DRAFT`，2026-10-04，待用户确认。设计继承 M29 的浅色工业数据库 IDE 和现有工作台，不代表生产样式已经迁移。

## 设计判断

使用者在同一连接里连续查询、检查、编辑和治理九种模型。最重要的是目标上下文稳定、数据可读、危险操作可核对。采用近白数据面、浅灰蓝框架、单一 Fluent 蓝交互色；保留 Segoe UI / 微软雅黑和 Cascadia 等宽数据字体。图标使用同一 1.6px 描边 SVG 系统，复用现有 SonnetDB logo。主界面无营销 Hero、装饰性卡片网格或大面积渐变。

## 五区外轮廓

```text
┌────────────────────── 顶部：品牌 / 目标上下文 / 命令 / 连接 / 账户 ──────────────────────┐
│ 一级轨 │ 左侧：导航或资源树 │ 中央：工作区页签 / 对象标题 / 二级任务 │ 右侧：检查器       │
│        │ 独立滚动与局部状态 │ 当前任务的数据、查询器、表单或画布    │ 选中对象或行       │
│        │                   ├─────────────────────────────────────┤ 原始值 / 元数据    │
│        │                   │ 下方：可收起的结果 / 计划 / 任务输出 │                    │
├────────────────────── 底部：连接 / 作用域 / 状态 / 面板与任务入口 ───────────────────────┤
└────────────────────────────────────────────────────────────────────────────────────────┘
```

顶部与底部固定。左侧、中央、检查器、结果区分别滚动。切换模型或主题不改变一级导航和工作区页签的位置。布局重用 M29 的组件职责，调整入口和上下文表达。

|---|---:|---|---|

## 顶部与导航层级

一级导航只表达任务领域。左侧只表达该领域的页面或资源。中央页签表达同时打开的工作；页签下方二级任务表达当前对象的操作。表格/JSON/图表是结果呈现选项，不与业务导航混排。

连接库在顶栏提供全局快捷入口，概览中的连接管理是同一资源的管理视图；不会建立第二套连接配置。查询、数据、Studio 的旧重复一级入口合并为工作台。AI Provider 与普通偏好分开，设置不再跳到 AI 配置。

数据库资源树统一显示九模型，SonnetMQ Topic 与时序、关系、文档、KV、向量、全文、对象和 Graph 并列。当前 `/v1/db/{db}/mq` 使用实际数据库授权，并以数据库限定 Topic 名称；MQ 标题、面包屑、页签和详情均显示逻辑数据库，例如 `factory / DeviceEvents`。数据库切换保留原草稿，并打开新命名空间中的对象，不把同名 Topic 当作同一资源。

MQ 检查器、配置和恢复任务另显示“物理持久化：实例 / .system/mq”。物理队列目录、Server 生命周期和整体快照/恢复仍属于实例管理；单库备份不覆盖该物理目录。M47 规划以 `scope` 表示逻辑名称/权限，以 `persistenceScope` 表示持久化/恢复边界，不通过外壳调整修改生产存储。图标与导航表达模型任务，不要求模型的底层文件使用同一种存储方式。Graph 在树、对象标题、页面目录和宿主矩阵保留 Beta。

## 对话框与提示的几何

- 小型表单：620px，本轮保留两列表单空间；短确认可收敛为 440–520px。
- 写审批与危险删除：720px；头部目标、范围/影响、预检、风险确认、固定底部动作。
- 大型字段映射和完整编辑放在中央工作区；不能塞进小模态。
- 设计目录：最大 1060px，仅供评审。正式产品没有“模拟状态”菜单。
- 下拉/弹出层逃逸滚动容器；持续离线、只读、错误、截断使用页面内 banner，复制等即时反馈使用 toast。

## 响应式合同

| 宽度 | 布局 |
|---|---|
| ≥1440px | 左导航 + 中央 + 可选常驻 Inspector；结果高度可调 |
| 1100–1439px | 左导航可见；Inspector 覆盖式，默认关闭 |
| 800–1099px | 左导航抽屉化；中央工作区保持完整；Inspector 另开覆盖层 |
| <800px | 巡检和只读查询；左右面板分别打开，编辑与批量治理转桌面 |

窄屏的数据表在表内横向滚动，整个 App 不横向滚动。底部结果不复制主列表。原型检查桌面 1600×1000、1280×900、1100×800、390×844；这不是 Studio 安装或 Extension Host 验收。

## 像素实现合同与顺序

1. 先确认外轮廓、目标上下文、七一级和所有页面归属。
2. 再确认二级任务、跨页签恢复、对话框和状态表达。
3. 按页面清单逐页确认真实数据量、长内容、控件与专用任务细节；规划端点不纳入“已有功能”像素验收。
4. 将获确认的 HTML、截图、token 与状态作为版本化基线，迁移共享外壳和宿主适配器。
5. 同视口、同缩放、同示例数据逐项比对。框架位置/尺寸优先；差异须可解释。字体渲染差异不能成为大范围布局漂移的理由。

本稿可用于外壳、导航、典型页面与共享流程评审。目录覆盖和通用状态模拟不等于每个真实端点、每个二级页面都已经完成最终像素稿；后续审批保持这一范围。
