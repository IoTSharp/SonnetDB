## 实际修复与验证

版本错配在修改前以同 SHA、旧版本的成功预检复现 `ready=true`。修复后分别验证 Publish 与 Connectors 的正式版本、预发布版本正例和错版、混版、无版本、标识大小写负例，同时拒绝通配符、尾换行等非法版本输入。版本限定名称由同一 SHA 下受信 workflow 的解析版本产生，该版本也传给实际包构建和库存/身份校验；不依赖运行标题或未验证的备注。

运行排序的确定性负例为：旧 run 在 00:00 开始、02:00 成功，新 run 在 01:00 开始、01:30 失败。原门禁错误选择旧 run；修复后选择新失败。回归同时覆盖旧 run 的较新 attempt、排队/运行中重跑、缺少开始时间时回退创建时间、空集合和 evaluator 失败传播。保守策略会让较早遗留的 queued/in_progress 候选继续阻断发布，必须结束或取消该运行后再核验。

版本与运行次序合同已在 Windows PowerShell 7 和 Linux .NET SDK 容器内通过。产物验证器的 16 项库存、身份、校验和及原生入口正负例通过；网络默认值合同通过。这些脚本 fixture 验证判定逻辑，真实包和在线参考服务仍由本轮提交的 Actions 验证。
