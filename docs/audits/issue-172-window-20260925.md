# GH-Issue #172 relation window acceptance (2026-09-25)

Source: [IoTSharp/SonnetDB#172](https://github.com/IoTSharp/SonnetDB/issues/172). The issue was already closed after the initial measurement-only `OVER` implementation. Its original relation-table request remained unmet; this branch adds that missing scope. This file records local source evidence only, not a release or remote deployment claim.

| Original acceptance | Local evidence |
|---|---|
| `OVER`, `PARTITION BY`, window `ORDER BY` | Existing parser AST supports all three. `SqlRelationalWindowTests.Parse_PartitionAndCompositeOrder_PreservesWindowSpecification` verifies two partition and two sort keys. |
| `ROW_NUMBER`, `COUNT`, `SUM`, `AVG`, `MIN`, `MAX` on relation tables | `RelationalWindowExecutor` computes each after relation filtering, before final pagination. Full-partition and ordered peer-frame regressions cover all six function names. |
| No-order behavior and deterministic numbering boundary | Aggregates without order read the whole partition. Relation `ROW_NUMBER` rejects missing window order. Equal sort keys use current input order as a tie-breaker; callers need a unique final key for repeatable ordinals. |
| NULL, duplicate keys, multiple partitions, empty input | `SqlRelationalWindowTests` verifies `COUNT(expr)` NULL elimination, null-only `SUM`, peer-aware `RANGE` default, composite partitions, NULL sort keys and empty table metadata. |
| SqlSugar-facing ADO boundary | Embedded `SndbConnection` executes a relation window query and returns `Int64` field types plus expected `ROW_NUMBER` and global `COUNT(*) OVER ()` values. Remote transport was not exercised here. |
| Ordinary aggregate combination | Same SELECT level `COUNT(*)` with window, `GROUP BY` with window, and `HAVING` with window are explicitly rejected; nested window expressions are rejected. |
| Measurement separation and performance | Measurement retains one series per partition and only `time ASC` window ordering. Relation windows materialize filtered input and sort each partition; ordered aggregate prefixes are recomputed per peer (worst-case O(n²)). Explicit `ROWS`/`RANGE` syntax remains rejected. |
