# GH-Issue #392：EF 关系迁移事务接线

截至 2026-11-05（Asia/Shanghai），本切片修复了 EF 生成的受支持关系 DDL 被统一标为事务外执行的问题；完整 EF 测试 318/318 通过。结果绑定本次源码补丁，**不表示公开的 5.0.0 Provider 已包含修复**。公开新包及真实应用迁移、EF 进程强杀与恢复仍未由本次验证覆盖，Issue 完整交付应继续保持开放。

## 复现与修复

原 `SonnetDbMigrationsSqlGenerator.EndDdlStatement` 无条件调用 `EndStatement(..., suppressTransaction: true)`。一条迁移先删除自引用外键、再新增列，随后因存量重复数据无法创建唯一索引时，前两条 DDL 已经单独提交。修复前的真实嵌入式迁移回归实际观察到失败后仍存在 `Transient` 列。

现有 #227 已提供关系 DDL workspace、提交 journal 与持久恢复，本次复用该能力。受支持关系 DDL 保留 EF 事务；成功时与种子数据、迁移历史一起提交，后续 DDL 或历史写入失败则回滚同一事务内的全部变更。`SqlOperation.SuppressTransaction` 的显式设置继续生效。

独立序列和 schema 不属于关系 DDL workspace，在通用 operation 分派期间单独标记为 transaction-suppressed，并在 `finally` 恢复生成器状态，避免后续关系 DDL 错误继承抑制标志。该分类不新增引擎原先不支持的序列变更、schema DDL 或跨模型事务。

本次没有修改二进制布局、目录版本、协议、Core 运行时依赖、公开方法签名或 JSON 序列化路径。既有永久目录 floor、约束、无损转换、自引用主键迁移、取消及预算限制继续适用。

## MigrationOperation 能力矩阵

| 操作 | 生成与执行范围 | 事务合同 |
| --- | --- | --- |
| `CreateTable`、`DropTable`、`RenameTable` | 现有持久关系表 DDL；具体名称及依赖仍由引擎校验。 | 保留 EF 事务。 |
| `AddColumn`、`AlterColumn`、`DropColumn`、`RenameColumn` | 现有受支持列演进；不放开自动增长/计算列等显式拒绝。 | 保留 EF 事务。 |
| `CreateIndex`、`DropIndex` | 现有关系索引；存量唯一冲突使当前迁移事务失败。 | 保留 EF 事务。 |
| `AddForeignKey`、`DropForeignKey`、`AddCheckConstraint`、`DropCheckConstraint` | 已有命名约束及引用/检查合同。 | 保留 EF 事务。 |
| `AddPrimaryKey`、`DropPrimaryKey`、`AddUniqueConstraint`、`DropUniqueConstraint` | 保留原生成路径；实际方言、名称及主键迁移限制不因事务标志扩大。 | 保留 EF 事务标志，非法操作仍由引擎拒绝。 |
| `InsertData`、`UpdateData`、`DeleteData` | 既有关系种子数据。 | 保留 EF 事务。 |
| migration history 的 `INSERT` / `DELETE` | 对应迁移记录；首次创建历史表仍是独立初始化。 | 普通历史行与当前事务组一起提交。 |
| `CreateSequence`、`DropSequence` | 已有无 schema、Int64、非循环序列；不承诺其它 EF 序列选项。 | transaction-suppressed，独立于关系表事务。 |
| `AlterSequence`、`RestartSequence`、`RenameSequence` | 不新增原引擎/Provider 不支持的变更或重命名。 | 分类为关系事务外；生成或执行仍可明确拒绝。 |
| `EnsureSchema`、`DropSchema` | 不新增原引擎/Provider 不支持的 schema 操作。 | 分类为关系事务外；不以生成 SQL 代表已支持。 |
| `RenameIndex` | 原生成器不支持。 | 继续在生成阶段拒绝。 |
| `AlterDatabase`、`AlterTable` 的注解变化 | EF 基类原来的无 SQL 路径；未新增注释或控制面操作。 | 没有命令时不产生提交边界。 |
| `SqlOperation` | 使用已有 SQL 方言。视图、measurement、用户/权限等事务外操作须显式设置 `suppressTransaction: true`。 | 严格尊重调用方设置；不会猜测文本并自动提交。 |

只包含受支持关系 DDL/DML 且没有事务抑制命令的迁移组具有原子提交边界。包含序列或其它显式事务外命令的迁移会被 EF 拆为多个提交组，不能将全迁移称为一次原子操作。回退仍须遵循升级前备份、目录 floor 及新写入回补合同。
