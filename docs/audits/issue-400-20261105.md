## 已有能力与本次变更

已有 `SonnetMqStore.CreateSnapshot` / `ReadSnapshotManifest` / `RestoreSnapshot` 及 source-generated manifest v1；现有实例级 gate 已协调发布、ACK/NACK、reset、retention 和 Topic 创建。Server DI 单例 owner 位于 `DataRoot/.system/mq`，现有 MCP 与 REST 复用这一实例并按数据库限定 Topic。现有两个核心快照正向测试、消息/ACK/NACK/去重/retention 回归和“原目录整体离线后分别恢复单库对象及 MQ”的真实用例继续复用。

目录模式增加生命周期租约，在 Replay 前取得，Dispose 后释放，快照排除锁文件；Server 现有 DI 通过相同 `Open` 自动采用该 owner 合同。旧版本 Server 不持租约，因此旧进程实际停机仍是操作者前提，不能靠新锁证明旧进程不存在。单文件模式不在新 CLI 范围。

修复原生快照/非覆盖恢复的真实竞态：原逻辑在初次验空后仍可能递归删除发布前出现的外来目标。现在先写唯一 staging，再以非递归空目录删除和原子移动发布；冲突保留外来字节，失败只清理本次 staging。manifest 格式、消息格式和显式 `overwrite=true` 的既有 API 语义没有扩展。

## 独立复核修正：锁文件大小写与异常关闭

原 14 文件补丁及原 delivery 清单保持不变；本修正以 `delta-baseline.json` 记录的四个旧文件 SHA 为基线，另交付增量补丁。

- Windows 实际锁文件名为 `SONNETMQ.LOCK` 时，OpenOrCreate 持有同一文件，但原 Ordinal 排除会将其当作快照数据。Core 快照与 CLI 清单现在共同按 Windows OrdinalIgnoreCase、Unix Ordinal 比较；原生及 CLI 实际快照覆盖此用例，Unix 上不同大小写的独立文件保持其原有数据语义。
- 任一 Topic 关闭阶段抛 IOException 时，旧流程跳过其它 Topic writer、冷读句柄缓存和单文件共享流，却在 finally 释放目录租约。现在逐项尝试关闭所有 owned 资源，再释放租约；单一异常用 ExceptionDispatchInfo 重抛原对象及原始堆栈，多项异常聚合保留，不吞 I/O 失败。测试只新增一个实例级 internal 钩子，在实际首个 Topic writer 已关闭后注入异常，没有替换产品 I/O 框架。
- 修复前新增三项实际回归 **0 PASS / 3 FAIL**：大小写锁导致 File.Copy sharing violation；目录与单文件模式均只观测到首 Topic 被关闭，并留下打开的消息文件。修复后新增回归连同原 MQ/CLI/备份组 **99/99 PASS、0 FAIL、0 SKIP**。回归同时检查余下 Topic 都尝试关闭、冷读缓存/共享流释放到可独占打开文件、目录租约在关闭期间仍排斥第二 owner、原 IOException 对象保留及干净重开继续发布。

原始 TRX 为 `issue400-delta-before.trx` 与 `issue400-delta-after.trx`，执行回执为 `mq-delta-before-result.json` / `mq-delta-after-result.json`；原始失败保留，不由后续 PASS 改写。基线失败因残留句柄导致夹具清理中途失败，精确残留路径及创建时间从原 TRX 核对后回收，回执 `delta-before-cleanup.json`；没有按宽泛目录前缀删除。最终统一整合与远端验证仍由主智能体执行。
