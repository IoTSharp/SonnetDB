## #335：同语义计数场景

`StatementTrigger_EquivalentCounterJourney_ReducesBodyExecutions` 对两条路径执行同一业务操作：
批量写入 N 行，每行 amount=2，同时把持久汇总的 amount 增加 2N、count 增加 N。
行触发器执行 N 次汇总 UPDATE，语句触发器通过 transition table 聚合后执行一次 UPDATE；两者校验精确相同的最终状态。

2026-09-06 本机 Debug 单次样本：Windows 10.0.26200，Intel Core Ultra 9 185H（16 核 / 22 逻辑处理器），.NET SDK 10.0.400。

逐行 outbox 的业务本来就需要 N 条明细，不能用汇总场景替代它的容量证据。

## #336：写入前归一化

测试固定了订单/客户输入的 LOWER/COALESCE 归一化、缺失值修复、金额规则及主外键改写。
这些场景需要把 NEW 变成满足约束的最终值；现有 AFTER 拒绝和回滚无法替代写入前改写。
合同详见 [SQL 参考](../sql-reference.md)：只允许受限赋值，OLD 只读，生成列不可改写，所有原有约束和并发校验保持生效。

## 实现边界

- AFTER STATEMENT 在空影响集也执行一次；UPDATE OLD/NEW 配对、INSERT SELECT、聚合/JOIN、嵌套快照及失败回滚纳入验证。
- transition set 持有事务行图像引用，不复制整个集合；行数和保守字节硬上限按同时存活的调用链累计，超限拒绝并回滚。当前无 transition set 磁盘 spill。
- BEFORE 只支持关系表 INSERT/UPDATE ROW，body 仅 SET NEW。DEFAULT/自增预留、顺序改写、ROWVERSION、NOT NULL 与最终事务约束的顺序已固定。
- 例程目录 v3 新增时机、粒度与别名，保留 v1/v2 读取；写入后旧版本引擎明确拒绝。主数据 FileHeader、KV 和 WAL 格式均未修改。
- 无 BEFORE DELETE/STATEMENT、INSTEAD OF、可写视图、deferred/constraint、多模型或跨库触发语义。
