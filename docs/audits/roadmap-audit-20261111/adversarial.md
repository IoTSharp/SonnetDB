## 1. 独立结论

1. 仓库并非“路线大部分都是空壳”。Graph Beta、持久窗口/订阅、CDC 桥接、RAG 摄取与 generation、查询预算、TAG 分组及 Int64 RLE 都有实现或局部交付证据；重复建设会损害可靠性与维护能力。
2. 当前最直接的路线问题是**状态漂移、任务粒度混杂和多份执行顺序并存**：某些总览仍写 planned，细表与源码已有切片；旧候选的发布流程与新源码可靠性任务竞争同一个“当前顺序”。
3. “只要存在 API 就算完整”同样不成立。typed 全文搜索存在可以从调用顺序直接确认的候选窗口语义缺口；M42 的累计保留预算不能覆盖整个进程 heap；持久运输/窗口不等于通用增量 SQL 或业务副作用 exactly-once。
4. “不丢数据”必须落实为指定持久性配置、确认点、故障模型和恢复不变量。进程强杀不等于设备掉电；快照范围也不能自动扩展到实例 MQ、外部 spool、provider 状态或其它恢复域。本轮没有得到可据以宣称现有默认引擎必然丢数据的新复现。

## 3. 需要优先于新应用扩张的现存功能缺口

### AR-07：typed 全文过滤、总数与分页只在候选窗口内计算

证据：`src/SonnetDB.Data/FullText/SndbFullTextClient.cs:376-404` 和 `src/SonnetDB/Endpoints/Routes/ManagementContractEndpoints.cs:752-775`：

- 搜索先取 `min(10000, offset + pageSize + 1)` 条命中，随后才应用 `Filter`。
- 过滤时以 `Scan(10000)` 构建文档字典；它还可能排除候选 ID 对应的真实文档。
- `TotalHits` 是过滤后的候选计数，facet 只遍历这些候选；它们不是完整过滤集合的统计。
- `hasMore` 用过滤后的 `candidates.Count` 与原始窗口比较。若第一页候选都不满足 filter，而窗口外有合法匹配，当前代码可返回零条且无后续 token。
- 嵌入式排序 `SndbFullTextClient.cs:430-441` 仅实现 ID 或 score；其它路径回落到 score，不能据配置中存在 sortable field 推导已支持字段排序。

这是重新确认的既有查询语义缺口，**本轮没有运行复现**；M48 设计第 44 行已记录它，不能冒称首次发现。`SndbFullTextModels.cs:58` 将 TotalHits 声明为“命中总数”、HasMore 为“是否还有下一页”，当前响应没有候选/截断关系字段，生态审查也确认这是公开 `/fulltext/search`，不是仅供预览的入口。它不证明磁盘数据已丢失，也不证明越权泄露。底层 `SearchFullTextFiltered` 已存在，不应重写整个全文引擎；应先建立“首窗口全部被过滤、窗口外才命中、超过 10000、纯过滤、分页总数/facet”的最小真实入口回归，再决定接线或明确拒绝/返回 lower-bound 的合同。

归属：M36 全文合同、M48-L08/L10/L11 的既有基础修复。此修复可独立交付，不需要等待完整 LogStream/看板/告警产品，也不需要等待一亿条/168 小时。

### AR-08：预算有局部实现，不能承诺整个查询/进程有界

`src/SonnetDB.Core/Sql/Execution/SqlExecutionOptions.cs:70-85` 将 `MaxMaterializedRows/Bytes` 设为可空的 opt-in 限额；`docs/benchmarks/m42-graph-result-bounds.md:3-9` 明确只限制支持路径的累计保留结果，并在不支持路径提前拒绝。图快照、底层页、瞬时属性解析不是 CLR heap 硬上限。

`docs/benchmarks/m45-measurement-tag-grouping.md:48-52` 明确 TAG 分组保留全部分组状态、最后物化，没有该切片提供的分组数/字节准入或 spill。`PersistentFullTextIndex.cs:925-940` 的合并快照会构造全部 live document；不能把 Top-K 或帧分包当作存储工作集上界。

这是已声明的容量/高并发限制，不是本轮 OOM 复现。下一步应以多个真实并发查询与后台维护共享的资源预算为交付，而非仅新增结果行数参数；高基数聚合、全文合并、快照/缓存竞争和拒绝/取消释放需要独立核验。

### AR-09：聚合 state 的数学合同存在注释错误

`src/SonnetDB.Core/Query/Functions/IAggregateAccumulator.cs:10-11` 把 `A+B == B+A` 称为结合律，并要求重复 merge 幂等。`tests/SonnetDB.Core.Tests/Query/Functions/AggregateStateValidationTests.cs:34-44` 明确连续两次 merge 会使 `Count` 从 1 增到 3；去重估计与样本计数不是同一语义。

因此 C02 不能仅靠“已有 Merge 方法”关闭。正确接续是区分结合律、交换律、顺序敏感性、统计状态与输入身份去重，明确各累加器能力，再做版本化通用 state；不能把注释错误直接写成当前所有查询会重计的运行故障。已有 Int64 完整身份与状态合法性守卫应保留，不重复实现。

## 6. 对主执行顺序的挑战与修订建议

主审提出“默认持久性与迁移恢复 → 共享预算与尾延迟 → 性能成本 → 时序语义/M50 → SDK生态 → M45 → M44/M48”的方向合理，但不能排成所有后项都等待所有前项生产资格通过的长链。

建议拆为可并行的三条线，每条线仍有明确所有者和验收范围：

1. **可靠性关键路径**：先核已确认写入、未知结果、升级/回退和备份恢复域；本地代码与确定性恢复回归完成即可交付对应切片。实际旧二进制、故障注入/满盘/ACK 后强杀归匹配候选；设备掉电、原规模与 168 小时归环境资格，不能使所有小修停工。
2. **查询与并发正确性路径**：全文候选窗口错误、接口数学合同、预算准入/释放可在可靠性代码旁独立推进。结果漏读和错误总数直接影响用户决策，应先于日志看板/新模型扩展。性能改动必须绑定正确性 oracle，不能用吞吐提高掩盖结果不完整。
3. **消费者与产品闭环路径**：只读/有界 SDK 小切片、已实现代码的真实消费者、安装与 CI 证据可并行；生产发布必须汇合适用安全/恢复门禁。不能因上游包未发而重开已完整实现的普通代码 issue。M47 已发布 Web 预览不重开，后续宿主单独核。

时序写入原子单元、分区/TTL、重复点策略与 M50 精度涉及真实业务语义和格式，必须先把决策与迁移合同冻结。当前请求是核查与路线整理，不授权自动改变这些语义、默认持久性或外部状态。

- **支持并限定**：MCP schema 测试断言至少 43 工具且验证读写提示/输出 schema，证明主线已有该工具切片；这是测试定义/实现审查，不是本轮真实 WorkBuddy 宿主验收。公开/平台/HTTPS 与工具源码切片必须分层。
- **支持并反驳过度优先化**：CAP 显式拒绝 `ConsumerThreadCount != 1`，并在 PostConfigure 再次防止放宽。这是有效的受支持边界。只有确有同组多活动实例需求时再实现 lease/fencing 与故障恢复；用户要求提升高并发并不自动授权移除保护或要求所有生态先横向扩展。
- **支持**：candidate12 的 Windows R1 Web 预览应归档；不得由其 P08 推导 Studio/VS Code、九模型完整管理或当前源码新发行完成。旧候选 NOT_READY 不应继续阻塞当前预览条目。
- **正反一致的现存缺口**：生态审查复核 AR-07 的公开 DTO/HTTP 入口和有限测试覆盖，支持优先补 typed 全文正确性；由于 M48 设计已承认该缺口，采用“既有缺口重确认”，不记为新事故。

最终接受“可靠性关键路径 + 查询/并发正确性 + 有范围的消费者闭环”并行推进。拒绝三种扩大结论：所有代码交付等待原规模长稳、全部既有能力重新开发、静态未验风险直接改写成数据丢失或安全事故。
