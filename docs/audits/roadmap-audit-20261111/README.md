## 正反质询后的排序决策

1. 确认写、默认迁移/回滚和组合恢复优先，因为这些路径直接接触已有数据。
2. 当前公开查询正确性和权限/预算并行前置；全文窗口缺口不应等待日志平台整体建设。
3. 进程/数据库资源治理与计量工具先于盲目加并发、缓存或算法。
4. 时序原子单元/重复/分区/TTL与精度先联合冻结，避免各自改格式后再返工；只排序，不代替用户语义决定。
5. .NET/C可靠消费者、小范围EF应用AOT、安装/固定硬件等按依赖独立推进，不把所有代码小修串到168小时门禁后面。
6. 增量计算、AI/日志应用、更多管理宿主和渠道扩张使用已完成底座，以具体业务价值决定投入。

环境资格单独运行：Demo/现场目标、固定硬件、物理掉电和长稳不进入普通代码切片的隐含阻塞链；环境路线只阻断对应 Preview/Beta/Production 或环境 issue。用户后续日志必须绑定候选、机器、时间窗、负载和故障；缺少电源/介质/完整性链路时只能报告 `UNKNOWN/NOT_RUN`。

反驳后撤回或避免的判断：不称九模型空壳；不重新实现K7已完成能力/旧group commit/MCP；不把缺公开包当代码未完成；不把历史Core UNKNOWN当最新CI失败；不以单次Parity success关闭七天观察；不以本轮静态疑点宣布数据泄露或丢数据；不因文档整理降低原验收阈值。
