# SonnetDB 固定讲解人物

| 项目 | 当前值 |

本档案规定 SonnetDB 讲解人物以及带人物的封面、图文和视频素材如何保持同一角色。用户已从三方向候选中选择 B；B-20261107 是当前唯一默认人物输入，延续 V5 的同一成年人物与服饰。V5 保留为历史批准基准，A、C 保留为历史候选，均不能自动替换当前 B 基准。

## 1. 批准状态与适用范围

- 用户于 2026-11-07（Asia/Shanghai）明确选择“B吧。然后提交并推送。”；本次 B 批准优先于历史 V5 默认输入规则，记录见 [B 定稿依据](assets/character/approval-20261107-b.json)。
- 本档案和 [基准清单](assets/character/manifest.json) 共同构成后续生成的长期入口，当前规范版本为 1.1、基准标识为 B-20261107。更换基准不代表另建人物身份或更换固定服饰。
- 本档案不要求每张纯技术图都出现人物，也不改变各渠道独立配图、查重、事实审核、单次发布请求和权限规则。
- 已发布文章、冻结稿、其他渠道原图和历史回执不自动替换；替换历史资产必须另有明确范围。
- 生成成功、审图通过、用户要求修订、上传和公开发表分别记录，任何一项都不能替代其他项。

## 3. 固定身份与造型

| 部位 | 必须保持 |
| --- | --- |
| 身份与年龄感 | 同一个成年亚洲女性，约 25 岁，成年人的五官和身体比例；不赋予姓名、生日或现实人物身份 |
| 脸与气质 | 以 B 为准、延续 V5 的同一张脸；甜美、可爱、亲切，自然温暖的微笑和清晰眼神，同时保持技术讲解员的专业感 |
| 发型 | 深棕色长发、自然微卷、轻薄刘海、小薄荷色发饰 |
| 上身 | 米白针织开衫及细薄荷包边、白衬衫 |
| 裙装与领结 | 薄荷绿、米白、少量淡粉线条的格纹百褶裙与同款蝴蝶结；比例和长度参考 B，延续 V5 固定造型 |
| 丝袜 | B 延续 V5 的近自然肤色、极轻冷薄荷调、细腻轻透光泽；自然肤色与膝部、小腿、脚踝的明暗清楚。薄荷绿主要体现在服饰中，不得画成灰黄绿或不透的亮青色块 |
| 鞋子 | 米白浅口包头高跟鞋、细收鞋跟、无厚重鞋台，轮廓以 B 为准，延续 V5 固定鞋型 |
| 角色识别 | 新主题可以改变动作和构图，但不能通过换脸、改发型、换发色或改变年龄感制造另一个人物 |

袜子的 8–12D、鞋跟约 5–6 厘米只能作为生成时的轻透和鞋型视觉描述，不能声称从 AI 图像验证了实物参数。腿部表现依靠自然明暗和细腻光泽，不靠高饱和色覆盖。

## 4. 渲染与拍摄质感

默认采用写实、自然皮肤和面料质感，柔和主光和适度轮廓分离；不改成动漫脸、塑料娃娃或过度商业化的广告质感。以下要求是默认的自然写实提示层，应根据渠道尺寸和主题取舍，但不能削弱固定身份和造型：

1. 去除 AI 常见的过度光滑质感，为皮肤、头发和衣服加入自然凹凸与细微纹理。
2. 避免过于完美的左右对称，采用接近日常拍摄的自然构图。
3. 优先重现从窗户进入的自然光和真实阴影，避免僵硬的工作室照明。
4. 不让所有区域都清晰无比；可加入手机拍摄常见的轻微抖动或焦点偏移，但脸部和教学重点必须可辨。
5. 不过度美化皮肤，保留自然毛孔、细毛和小皱纹；不得把瑕疵处理成污渍或失真。
6. 不过度整理背景，可加入与主题相符的生活化小物件或自然层次，但不能遮挡人物和技术图示。
7. 画面可以像普通人用手机记录的日常讲解瞬间，仍须保持成年、得体、专业和可用于 SonnetDB 内容的清晰度。

配色先统一人物与场景的冷暖关系：脸、手和腿保持一致的自然肤色色温，保留关节正常明暗，避免膝部红色块、脚踝发白、胫骨细长白亮线或绿色腿部阴影。米白衣鞋、薄荷格纹和少量淡粉线应相互协调；窗外高亮、绿色反射和地面纹理不能抢走脸部重点。

全身构图要核对自然承重、膝盖与脚尖方向、膝踝轮廓和双鞋接地阴影，保持当前 B 基准的自然成年比例。不能靠继续拉长小腿、缩小膝盖或收尖脚踝修饰体态。新配色或站姿示例属于待用户评审的衍生图，不自动替换已批准的 B 基准。

## 5. 可变项与背景

每篇可以改变教学主题、已核技术图示、道具、动作、画面视角、横竖构图、留白和渠道尺寸。改变这些不等于更换人物；换脸、改发型、换发色、改变年龄感、换装、换鞋或改变固定材质，需要用户新的明确要求。

背景可随文章主题变化，但人物与背景必须清楚分离。默认使用低饱和、较深冷蓝灰的技术场景，以柔和窗光和真实阴影衬托浅色服装与肤色；必要时只作克制的轮廓补光，避免棚拍感。避免整片浅暖背景使人物和裙装混在一起，也不让强烈背景图示盖过人物脸部和教学重点。

保持自然讲解姿态。全身角色参考须完整看清双鞋和鞋跟；文章封面可按构图裁切，脸部仍须清楚，不能通过裁切掩盖不符的造型。

## 6. 生成、审图和发布前检查

1. 读取本档案、manifest 和模板，核对 B 输入路径、尺寸和 SHA；将实际输入路径与 SHA 写入本次记录。
2. 使用批准模型和全身参考图进行编辑或参考生成，填入本篇已经核实的主题、技术事实、图示和文案。只在必要文字和图示区域留白，不重新设计角色。
3. 保存提示词、模型、请求尺寸、实际尺寸、输出 SHA、来源和失败/未知记录；遵守技能和渠道的总时限、次数、取消和进程回收规则，密钥不得落盘。
4. 目视核对同一脸部、成年甜美气质、长发、格纹和开衫、轻透丝袜、自然腿部明暗、高跟鞋、背景分离、肢体和透视。
5. 核对中文可读性、SonnetDB 品牌和文章技术内容。不得创造性能数字、客户成果、零丢失或生产就绪声明；涉及 Graph 时保留 Beta。
6. 角色或内容不符时先修正并重新审核。用户要求的新主题、新构图和新输出文件不等于更换人物。
7. 发布前单独记录生成、审图、用户确认、平台上传和公开读回状态；未确认的项不得写成已发布。

“每篇独立配图”表示新主题、新构图和新输出文件，不表示每篇换一个人。参考图是输入，不能直接冒充渠道要求的每篇新人物图；每篇输出都要保留新的输出 SHA 和事实审核。

设计须有独立判断，以配色协调、视觉中心、角色识别、轻透材质和缩小为封面后的可读性为依据。不得机械照搬最新参考，也不得在没有受众调查时宣称“大多数人更喜欢”。

## 8. 责任边界

本档案约束后续 SonnetDB 讲解人物及带人物的封面、图文和视频素材。它不替代渠道事实核查、独立配图、查重、权限和发布流程。

本档案和批准基准的入库不代表发布文章、上传平台素材、替换历史资产或部署产品。
