# SonnetDB 发布标题与开篇规则

用户于 2026-10-09 要求：后续文章的标题以 `SonnetDB` 开头，正文首个介绍段明确说明 SonnetDB 及本文主题。已经满足时保留。一级标题、链接或正文后段出现项目名，不能代替首段介绍。

准备稿先补齐项目名，再核当前事实、最终标题、完整正文及 SHA，重新通过平台预演和本地检查后才进入发布流程。各渠道副本独立维护。已经尝试提交的冻结稿、请求、日 marker 和历史回执不覆写，先只读对账。

已发表的本项目系列优先在原 ID 修改标题，保留 URL、全文和发布设置。保存原标题别名、原正文 SHA、单次编辑及独立完整回读；原题与新题共同查重。编辑结果未知时保留原 ID，不能删除、导入新文章或重复创建。

| 渠道 | 原有排期与额度 | 执行入口与核验 |
| --- | --- | --- |
| 博客园 | Asia/Shanghai 每天 11:00，最多两篇新文章 | `publish-cnblogs`；`verify-project-identity.ps1` 核标题/front matter/H1、首段和 SHA；历史标题记独立 `title-updated`，保持发布计数与旧题别名。 |
| OSChina | 同时区每天 11:00，最多两篇新博客；动弹独立 | `publish-oschina`；待发副本保留原题用于查重；原 ID 编辑单独保存 `titlePrefixCorrection` 与 `currentRemoteTitle`，原发布回执和稿件不改写。 |
| CSDN | 同时区每天 11:00，最多十次实际写入，与平台更小余额取小 | `publish-csdn` 的 `references/branding.md`；历史标题编辑与新发布、失败、已授权修复共用十次预算；原 ID、正文 SHA、marker 与强制重载全文核验。 |
| 微博 | 同时区每天 11:00，最多一套文章与配套微博 | `weibo-publisher`；网页优先，新文章预占检查标题和实际正文首段；旧 API 双输出未决结果仍阻断新创建。本人登录报告与实际工具观察分别记录。 |
| X | 本人手动发布，原自动任务暂停 | `sonnetdb-x-publisher`；英文稿标题如有则以 SonnetDB 开头，第一句点明项目；不恢复 API 或自动发布。 |

原有普通项目发布授权继续有效。支持私信需另有明确授权。准备稿、离线测试、保存草稿、接口接受、全文核对及公众可见性分别记录，不能互相代替。

各平台的权威回执仍留在本渠道账本。本文件只定义长期编辑规则，实时完成数、未知请求和未完成顺序见各渠道状态及根 `HANDOFF.md`。
