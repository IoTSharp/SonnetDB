# UInt64 字符串解析

`parse_uint64(text)` 将约定格式的字符串解析为 `0..18446744073709551615` 范围内的整数，以已有 SQL `DECIMAL(20,0)`、CLR `System.Decimal` 精确返回。解析全程不经过 Double 或有符号 Int64，也不新增存储类型、文件格式或协议值类型。

```sql
SELECT parse_uint64('18446744073709551615'); -- Decimal：18446744073709551615
SELECT parse_uint64('9223372036854775808');  -- Decimal：9223372036854775808
SELECT parse_uint64(' +00042 ');            -- Decimal：42
SELECT parse_uint64(NULL);                 -- NULL
SELECT parse_uint64(@text) FROM messages;  -- 参数/列使用同一规则
```

函数只接受 STRING 或 NULL。输入长度为 1..1024 个 UTF-16 代码单元，包含符号及空白；在此预算内允许任意数量的前导零。可接受语法为：

```text
ASCII空白*  '+'?  ASCII数字+  ASCII空白*
```

ASCII 空白仅为 U+0020、TAB、CR、LF、VT、FF；数字仅为 `0..9`。当前系统区域、数据 collation 和 Unicode 数字类别均不影响解析。`+` 与首个数字之间不能有空白；内部空白一律拒绝。NULL 传播，不触发文本校验。

以下输入均返回 SQL 执行错误，不截断、舍入或饱和：

| 输入 | 原因 |
| --- | --- |
| `''`、仅空白、`'+'` | 缺少数字 |
| `'-1'`、`'-0'` | 所有负号均拒绝 |
| `'2.9'`、`'2.0'`、`'1e2'` | 不接受小数点或指数 |
| `'1,000'`、`'0xFF'` | 不接受分组分隔符或其它进制 |
| `'１'`、`'١'`、不换行空格 | 不属于约定 ASCII 语法 |
| `'1'` 后带 NUL | 不接受尾随 NUL |
| `'18446744073709551616'` | 超过 UInt64 最大值 |
| 超过 1024 代码单元 | 超出解析预算，包括全前导零或全空白 |
| 数值、布尔、日期或 BLOB 参数 | 不做隐式字符串转换 |

这是有界、明确约定格式的 SQL 函数，不宣称与 CLR `UInt64.Parse` 的所有重载、区域或 `NumberStyles` 完全等价。尤其 `-0`、尾随 NUL 和超长前导零可能属于某些 CLR 解析路径的接受集合，本函数仍明确拒绝。Provider 若映射 `ulong.Parse`，必须公开这一服务端语法/长度边界，并拒绝无法等价处理的区域和样式重载；不能用宽松 `CAST(... AS DECIMAL)` 代替验证。

关系投影即使为空结果或全 NULL，仍声明 Decimal、precision 20、scale 0。可空性继承输入：已知非空文本为非空，可空列/NULL 为可空，无法静态确认时保持未知。输出不继承输入列的主键、自增或 ROWVERSION 属性；同名用户函数覆盖时使用该用户函数的未知声明，不能误标为内置 Decimal。

合法结果可以保存到现有 DECIMAL 列、参加精确 Decimal 比较和算术。范围校验只适用于本函数的解析结果；后续 Decimal 运算仍遵循现有 Decimal 合同，例如 `parse_uint64('18446744073709551615') + DECIMAL '1'` 可以得到超过 UInt64 范围的 Decimal，不将通用 Decimal 类型改为 UInt64。字符串解析与浮点/Decimal 转整数、一般 UInt64 参数绑定及 #259 的按位运算分别处理。

列、常量和字符串参数通过同一函数执行；关系 INSERT/UPDATE 后续行解析失败时遵循既有语句原子性。嵌入式、REST 和 h2c 使用相同的 Decimal 值与声明。h2c 的只读查询使用 Frame，写入/事务仍使用 HTTP/2 REST，不称为 Frame 写入。
